## Confirmed release findings

### P1 — Browser recovery leaves stale derived values and actions

`public/app.js:649–674` replaces climate and marks source chips live without
rebuilding `payload.metrics`, summary or operations, consumed at `:4726–4728`.
Independent in-memory execution of the actual function recovered heat 23°C,
AQI 15 and rain 0 while metric payload stayed 30°C, 77 and 4.3mm; summary and
operations were byte-identical. This is a latent recovery-path bug, not proof
that the currently inspected successful bake used these fixture numbers.

Action: derive all climate consumers consistently from the accepted reading.

### P1 — One-shot recovery and response ownership

The global `climateClientTried` flag blocks every later payload's recovery,
although boot replaces the payload every 60 seconds. Two successive degraded
fixtures made requests only on the first. A failed first attempt cannot retry
until reload. A deferred old completion also called `renderDashboard(old)`
after a newer payload had been installed.

Action: bounded retry/cache lifetime plus payload/request identity; do not
overwrite newer unrelated observations.

### P1 — Empty hourly data is accepted as live

`public/app.js:584–585,620–621` and `server.mjs:1385–1386,1506–1507` use `.every`
without testing slice length. Actual server/client loaders accepted empty
hourly value arrays alongside valid timestamps/current/daily fields as live,
producing empty histories and NaN forecasts (null after JSON serialization).

Action: exact window length, finite values and continuous timestamps, backed by
behaviour tests against all four loaders.

### P2 — Fresh retrieval can conceal stale observation

Actual loaders accepted complete fixtures dated 2020 and 2030, wrote updatedAt
as execution time and discarded the upstream observation timestamp. Completion
also skips an old baked status of live. The main card provenance currently
prints literal “60 s” / “15 min” / “live”, not observation age; live screenshot
showed those captions alongside a multi-hour baked payload.

Action: preserve source time and retrieval time separately, validate future/
stale/gapped data, expose honest age/tier in the cards.

### P2 security — External text reaches HTML sinks

Actual MET normalization preserves heading markup. Server metric construction
copies it into context, inserted unescaped at `public/app.js:1193`; warning
heading is also inserted raw at `:4808`. An isolated renderer harness retained
an image event-handler payload as HTML. This affects static baked snapshots.
WAQI pollutant text similarly reaches a tooltip (`server.mjs:2576` to app
`:1493`). No malicious real upstream record or active compromise was observed.

Optional City Reporter status also reaches raw tooltip HTML (`:1516`);
uppercasing does not neutralize character-reference payloads. Database write
permissions/constraints were not inspected, so public attacker control is
unverified. Do not treat the optional feed as trusted markup.

Action: context-appropriate text escaping and hostile-record regression tests.
Current CSP has no script-src restriction and does not block these handlers.

### P2 security — Local server can exit on malformed Host

`server.mjs:4897` parses request URL/Host outside error handling in an async
callback; default binding at `:13` is all interfaces. Actual extracted callback
executed in an isolated child process with malformed Host exited code 1 with
ERR_INVALID_URL. No socket or live attack was used. **Cloudflare Pages is not
this Node server and is unaffected.**

Action: 400 on malformed requests, loopback default for documented local use,
isolated-process survival test. No demonstrated static traversal was found.

### Correct a reported harness lesson before reusing it

The installed Python3.9.6 `http.server.__main__` defines
`DualStackServer(ThreadingHTTPServer)` and passes it to `test()`. Its default
server class also uses ThreadingHTTPServer. Therefore “python3 -m http.server
is single-threaded” in tasks/lessons.md is false here; the alleged module-import
deadlock cause is unproven. Live IAB rendering succeeded in this audit. A capture
taken immediately after viewport resize was temporarily scaled incorrectly;
re-capturing the settled viewport produced the correct screenshot. Do not turn
one failed harness run into a permanent product or tool diagnosis.
